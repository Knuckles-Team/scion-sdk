# SCION-OBSERVABILITY-FEEDS requirements

| ID | Requirement | Verification |
|---|---|---|
| `SCION-OBSERVABILITY-FEEDS-R001` | **RUM, security-audit, and CI/CD events join the durable source pipeline.** RUM, security-audit, and CI/CD events enter the same durable source pipeline as other systems of record, carrying a standard event envelope with stable identity, event, observed, and ingest times, actor and target references, and schema version; the adapter contract does not itself interpret an event as a verified incident, vulnerability, release, or user outcome. | Conformance tests using synthetic RUM, audit, and CI/CD event fixtures asserting correct envelope fields, idempotent event identity, and schema-drift quarantine behavior. |
| `SCION-OBSERVABILITY-FEEDS-R001.1` | **Rejected page identity isolation.** A page that fails validation cannot add event identities to the adapter tracker. A later retry of its valid events must emit them. This guard does not prove durable acceptance or restart recovery. Caller chain: `scion_sdk/adapters/event_feed.py` → `scion_sdk/adapters/event_envelope.py` (also imported by `scion_sdk/adapters/event_feed_bindings.py`), reached from the served test `tests/test_event_feeds.py::test_rejected_page_does_not_poison_event_identity`. Shape: files `scion_sdk/adapters/event_envelope.py`, `scion_sdk/adapters/event_errors.py`, `scion_sdk/adapters/event_feed.py`; it extends the existing code rather than adding a new component. | `tests/test_event_feeds.py::test_rejected_page_does_not_poison_event_identity` |
| `SCION-OBSERVABILITY-FEEDS-R001.2` | **Event identity receipt boundary.** Promote staged identities only after the worker validates the matching sink receipt. A failed or uncertain submission must not discard records on retry. Caller chain: `scion_sdk/adapters/event_feed.py` → `scion_sdk/adapters/event_envelope.py` (also imported by `scion_sdk/adapters/event_feed_bindings.py`), reached from the served test `tests/test_event_feeds.py::test_event_identity_waits_for_worker_acceptance`. Shape: files `scion_sdk/adapters/event_envelope.py`, `scion_sdk/adapters/event_errors.py`, `scion_sdk/adapters/event_feed.py`; it extends the existing code rather than adding a new component. | `tests/test_event_feeds.py::test_event_identity_waits_for_worker_acceptance` |
| `SCION-OBSERVABILITY-FEEDS-R001.3` | **Durable event receipt proof.** A running graph accepts the page and returns the matching durable receipt. Restart the worker and prove a retry neither loses nor duplicates an event. Caller chain: a connector imports the SDK public entry point `scion_sdk/adapters/event_feed_bindings.py`, exercised by the served test `tests/test_event_replay_checkpoint.py::test_restart_worker_process_against_real_graph`. Shape: files `scion_sdk/adapters/event_feed_bindings.py`, `scion_sdk/runner/syncing.py`, `scion_sdk/sinks/epistemic_graph.py`; it reuses the existing `scion_sdk.adapters.event_envelope`, `scion_sdk.adapters.event_feed` helpers instead of adding a parallel implementation. | `tests/test_event_replay_checkpoint.py::test_restart_worker_process_against_real_graph` proves OF-06 when the optional graph server is installed. |
| `SCION-OBSERVABILITY-FEEDS-R001.4` | **Event adapter registration.** The sync command discovers and activates a certified event-feed adapter from a declared feed kind. A served connector run reaches the adapter through the standard registry. Caller chain: `scion_sdk/adapters/platform_admission.py` → `scion_sdk/discovery.py` (also imported by `scion_sdk/runner/cli.py`), reached from the served test `tests/test_event_runner.py::test_declared_event_feed_reaches_served_worker`. Shape: files `scion_sdk/discovery.py`, `scion_sdk/ingest/live_declaration.py`, `scion_sdk/mcp/tool_surface.py`; it reuses the existing `scion_sdk` helpers instead of adding a parallel implementation. | Exercise connector-sync with a registered event source and a real MCP endpoint. Test: `tests/test_event_runner.py::test_declared_event_feed_reaches_served_worker`. |
| `SCION-OBSERVABILITY-FEEDS-R001.5` | **Event adapter entry points.** The SDK distribution registers its RUM, security-audit and CI/CD event bindings under their feed-kind names in the source-adapter group. Loading still requires an activation policy for the exact extension identity. Runner construction and a served connector run remain R001.4. Caller chain: `scion_sdk/adapters/event_feed_bindings.py` → `scion_sdk/adapters/event_feed.py`, reached from the served test `tests/test_event_feed_registration.py::test_event_feed_entrypoints_require_certified_identity`. Shape: files `scion_sdk/adapters/event_feed.py`, `scion_sdk/discovery.py`, `scion_sdk/manifest/presets.py`; it reuses the existing `scion_sdk.adapters.event_envelope`, `scion_sdk.adapters.event_feed_records`, `scion_sdk.adapters.event_feed_validation` helpers instead of adding a parallel implementation. | `tests/test_event_feed_registration.py::test_event_feed_entrypoints_require_certified_identity` |
| `SCION-OBSERVABILITY-FEEDS-R001.6` | **Exact accepted event-page replay.** Bind a bounded digest of the last accepted event page and adapter identity to its checkpoint. A fresh adapter may skip that page only if its checkpoint stays unchanged. The adapter submits a different page at the same event time. This does not prove general identity history or process restart recovery. Caller chain: a connector imports the SDK public entry point `scion_sdk/adapters/event_feed_bindings.py`, exercised by the served test `tests/test_event_replay_checkpoint.py::test_exact_page_replay_keeps_distinct_same_time_event`. Shape: files `scion_sdk/adapters/event_feed_bindings.py`, `scion_sdk/runner/syncing.py`, `scion_sdk/sinks/epistemic_graph.py`; it reuses the existing `scion_sdk.adapters.event_envelope`, `scion_sdk.adapters.event_feed` helpers instead of adding a parallel implementation. | `tests/test_event_replay_checkpoint.py::test_exact_page_replay_keeps_distinct_same_time_event`; optional graph readback `test_fresh_worker_replays_against_real_graph`. |
| `SCION-OBSERVABILITY-FEEDS-R001.8` | **Bound the adapter identity index.** Limit retained event identities by entry count and UTF-8 byte count, including a staged page. Refuse a new identity at the bound without changing the accepted state or checkpoint. Known duplicates and conflicts still resolve. No automatic eviction or reset is implied. Caller chain: `scion_sdk/adapters/event_feed.py` → `scion_sdk/adapters/event_envelope.py` (also imported by `scion_sdk/adapters/event_feed_bindings.py`), reached from the served test `tests/test_event_feeds.py::test_event_identity_capacity_preserves_known_entries`. Shape: files `scion_sdk/adapters/event_envelope.py`, `scion_sdk/adapters/event_errors.py`, `scion_sdk/adapters/event_feed.py`; it extends the existing code rather than adding a new component. | `tests/test_event_feeds.py::test_event_identity_capacity_preserves_known_entries` and `test_identity_capacity_refuses_page_without_advancing_checkpoint`. |
| `SCION-OBSERVABILITY-FEEDS-R001.7` | **Optional event tenant binding.** When the host supplies an expected tenant, verify each event envelope before identity deduplication. A mismatch refuses the page before sink submission. The host must supply a trusted tenant; omitting the binding does not establish isolation. Caller chain: `scion_sdk/adapters/event_feed.py` → `scion_sdk/adapters/event_envelope.py` (also imported by `scion_sdk/adapters/event_feed_bindings.py`), reached from the served test `tests/test_event_feeds.py::test_bound_tenant_refuses_before_duplicate_classification`. Shape: files `scion_sdk/adapters/event_envelope.py`, `scion_sdk/adapters/event_errors.py`, `scion_sdk/adapters/event_feed.py`; it extends the existing code rather than adding a new component. | `tests/test_event_feeds.py::test_bound_tenant_refuses_before_duplicate_classification` and `test_bound_tenant_refusal_preserves_sink_checkpoint`. |
| `SCION-OBSERVABILITY-FEEDS-R002` | **Host profile feed.** A connector-facing feed delivers `HostProfile{host_iri, cores, memory_bytes, storage_bytes, capabilities}` records into medulla `SourceIngest` as observation-class facts. The SDK defines the contract and the conformance kit run. Medulla owns the vocabulary `placement:HostProfile`. Depends on `MEDULLA-PLACEMENT-R700.3`. Caller chain: the owning rule in `specs/scion-observability-feeds/spec.md`, enforced through its test-spec entry. Shape: the rule lives in `specs/scion-observability-feeds/requirements.md` and its test-spec entry; it adds no production file. | Test: conformance kit case `host_profile_feed_ingests_observations` (L3) with an in-process served connector. Planned test: `tests/test_host_profile_feed.py::test_host_profile_feed_ingests_observations`. |
