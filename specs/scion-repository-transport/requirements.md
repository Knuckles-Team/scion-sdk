# SCION-REPOSITORY-TRANSPORT requirements

| ID | Requirement | Verification |
|---|---|---|
| `SCION-REPOSITORY-TRANSPORT-R001` | **Repository transport hydrates code and specification sources from Git.** The SDK fetches an authenticated, immutable repository revision and pages its file blobs and tombstones to the graph service's generated IndexRepository operation, letting a contributor hydrate both code and specification sources from their own Git provider without the SDK inventing symbol or semantic identity itself. Caller chain: `scion_sdk/repository/indexing.py` → `scion_sdk/repository/__init__.py` (also imported by `scion_sdk/repository/local_git.py`), reached from the served test `tests/test_repository_transport.py::test_pages_are_combined_into_one_native_repository_batch`. Shape: files `scion_sdk/repository/__init__.py`; it reuses the existing `scion_sdk.repository.errors`, `scion_sdk.repository.indexing`, `scion_sdk.repository.local_git` helpers instead of adding a parallel implementation. | Integration tests using a local Git fixture that submit a revision through IndexRepository and confirm the graph service, not the SDK, produces the resulting symbol and specification identities. Test: `tests/test_repository_transport.py::test_pages_are_combined_into_one_native_repository_batch`. |
| `SCION-REPOSITORY-TRANSPORT-R002` | **SDK is the sole path for repository hydration.** Stage: connector conformance for repository hydration. Hydration means sending repository files to the engine `IndexRepository` operation. Caller chain: `scion_sdk/testing/plugin.py::pytest_collection_modifyitems` runs `CHECKS` in each connector repository. Code: add `check_repository_hydration(resolved)` in `scion_sdk/testing/_conformance_static.py` and register `Check("repository_hydration", "SCION-REPOSITORY-TRANSPORT-R002", ...)` in `CHECKS`. Rule: walk `trees(resolved)`. Finding `HYDRATION_OUTSIDE_SDK`: an attribute call named `index_repository`, or the name `IndexRepository`, in connector code. Finding `HYDRATION_PRIVATE_IMPORT`: an import from a `scion_sdk.repository._*` module. A connector hydrates only through `scion_sdk.repository.index_repository_snapshot`. Local git use for a developer workspace, such as clone or worktree, is not hydration and is not flagged. The repository connector serves hydration through the tool `rm_repository_hydrate`, the production caller of `index_repository_snapshot`. The owner spec CONN-REPOSITORY-MANAGER-CONNECTOR-CONTENT holds that tool row. Refusals: each finding fails the check and names file and line. Writes: none. Depends on: SCION-REPOSITORY-TRANSPORT-R001. Shape: files `scion_sdk/testing/plugin.py`, `scion_sdk/testing/_conformance_static.py` define `pytest_collection_modifyitems`; it reuses the existing `scion_sdk.connector`, `scion_sdk.connector_identity`, `scion_sdk.testing.conformance` helpers instead of adding a parallel implementation. | Test: `tests/test_repository_hydration_conformance.py::test_direct_index_repository_call_fails_the_check` (L2) runs the check on a leaking fixture and a clean fixture. Test: `tests/test_repository_hydration_conformance.py::test_connector_plugin_runs_the_hydration_check` (L3) asserts that the plugin collects `repository_hydration`. |
| `SCION-REPOSITORY-TRANSPORT-R003` | **Repository ref walk traverses each Git tree once with batched reads.** The repository transport's walk phase visits each distinct Git tree only once and reads objects in batches, using a recursive tree listing and a batched object-read call or an equivalent provider batch API, rather than issuing one call per object, since object-tree traversal is a dominant pre-parse cost on a large repository. Caller chain: `scion_sdk/repository/__init__.py` → `scion_sdk/repository/errors.py` (also imported by `scion_sdk/repository/indexing.py`), reached from the served test `tests/test_repository_refwalk_fastpath.py::test_distinct_commits_with_one_tree_walk_once`. Shape: files `scion_sdk/repository/errors.py`, `scion_sdk/repository/local_git.py`, `scion_sdk/repository/walk.py`; it extends the existing code rather than adding a new component. | A before/after benchmark on public medium and large repository fixtures with cold and warm caches, reporting clone, fetch, walk, and submit timings separately and confirming output and refusal semantics are unchanged. Test: `tests/test_repository_refwalk_fastpath.py::test_distinct_commits_with_one_tree_walk_once`, `tests/test_repository_refwalk_fastpath.py::test_batch_matches_git_recursive_listing`. |
| `SCION-REPOSITORY-TRANSPORT-R004` | **Repository transport submits bounded, outcome-complete index batches.** The repository transport authenticates before fetching, pages file blobs and tombstones within the default batch-size bounds, and submits each batch to the graph service's IndexRepository operation with a per-file outcome, so no blob is silently skipped and a batch is accepted only when requested and returned identity, path set, outcomes, and digest all agree. Caller chain: `scion_sdk/repository/indexing.py` → `scion_sdk/repository/__init__.py` (also imported by `scion_sdk/repository/local_git.py`), reached from the served test `tests/test_repository_transport.py::test_batch_limits_create_one_call_per_bounded_batch`. Shape: files `scion_sdk/repository/__init__.py`; it reuses the existing `scion_sdk.repository.errors`, `scion_sdk.repository.indexing`, `scion_sdk.repository.local_git` helpers instead of adding a parallel implementation. | Tests against synthetic Git fixtures asserting a too-large file or missing per-file outcome is refused and an oversized or misaligned batch cannot produce a complete indexing receipt. Test: `tests/test_repository_transport.py::test_batch_limits_create_one_call_per_bounded_batch`, `tests/test_repository_transport.py::test_oversized_file_fails_before_engine_call`. |
| `SCION-REPOSITORY-TRANSPORT-R005` | **Branch-aware transport batches indexing into one call per batch.** Repository ingestion submits one batched IndexRepository call per bounded batch of files rather than issuing a separate round trip for each file, eliminating a per-file request loop as the dominant network cost of a large-repository ingest. Caller chain: `scion_sdk/repository/indexing.py` → `scion_sdk/repository/__init__.py` (also imported by `scion_sdk/repository/local_git.py`), reached from the served test `tests/test_repository_transport.py::test_batch_limits_create_one_call_per_bounded_batch`. Shape: files `scion_sdk/repository/__init__.py`; it reuses the existing `scion_sdk.repository.errors`, `scion_sdk.repository.indexing`, `scion_sdk.repository.local_git` helpers instead of adding a parallel implementation. | A test asserting the number of IndexRepository calls scales with the number of batches, not the number of files, for a repository fixture exceeding one batch size. Test: `tests/test_repository_transport.py::test_batch_limits_create_one_call_per_bounded_batch`. |
| `SCION-REPOSITORY-TRANSPORT-R006` | **Provider pages respect their requested bound.** Count snapshot files and tombstones together. Each count must fit the requested size. Tree entries must also fit the requested size. The SDK refuses an oversized page before processing its contents. A failed later page does not undo batches already submitted. Caller chain: `scion_sdk/repository/__init__.py` → `scion_sdk/repository/errors.py` (also imported by `scion_sdk/repository/indexing.py`), reached from the served test `tests/test_repository_refs.py::test_ref_walk_rejects_oversized_tree_page`. Shape: files `scion_sdk/repository/errors.py`, `scion_sdk/repository/local_git.py`, `scion_sdk/repository/models.py`; it extends the existing code rather than adding a new component. | Tests reject oversized pages from both provider ports. No entry from a refused snapshot page reaches the graph. Test: `tests/test_repository_refs.py::test_ref_walk_rejects_oversized_tree_page`, `tests/test_repository_transport.py::test_oversized_provider_page_refuses_before_page_submission`. |
| `SCION-REPOSITORY-TRANSPORT-R007` | **Local Git blob reads stay within the selected revision.** The local provider binds its repository and provider identity to the request. It checks the immutable commit resolves to the requested tree. It fetches only immutable blob IDs listed in that tree. Missing or mismatched identities refuse before blob read. Caller chain: `scion_sdk/repository/__init__.py` → `scion_sdk/repository/errors.py` (also imported by `scion_sdk/repository/indexing.py`), reached from the served test `tests/test_repository_refwalk_fastpath.py::test_local_blob_read_is_bound_to_selected_commit`. Shape: files `scion_sdk/repository/errors.py`, `scion_sdk/repository/local_git.py`, `scion_sdk/repository/walk.py`; it extends the existing code rather than adding a new component. | A local Git fixture requests a listed blob, an unreferenced blob, and a tree from another commit. Only the listed blob is returned. Test: `tests/test_repository_refwalk_fastpath.py::test_local_blob_read_is_bound_to_selected_commit`. |
